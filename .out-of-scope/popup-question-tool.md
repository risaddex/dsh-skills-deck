# 弹窗式提问工具（已改判，见 #43）

**状态：2026-11-17 起，提示词改为优先使用 agent 自带的提问工具；本文件不再表示「不采纳」。** 维护者在 [#43](https://github.com/risaddex/dsh-skills-deck/issues/43) 推翻了 2026-10-28 的决定：随包发布的提示词告诉 agent，harness 有原生提问工具（如 `ask_user_question`，每个问题可给多个选项），要优先用它，而不是在回复里手写「❓ Q1、Q2……」。

## 现在的做法

- `config/prompts/shared-sections.yaml` 的 `sharedTools`（中英各一份，二十条模板共用）新增一行：需要用户拿主意时优先用提问工具；没有这类工具的会话里才在回复里手写提问。是「优先」，不是「只许」。
- `tpl.diagnose` 的收尾句不再规定只能手写「❓ Q1、Q2、Q3」，保留「每个决定一个问题、逐个给推荐答案」。
- 当时不采纳的理由里「卡片只装得下选项标签、人点选时看不到方案全貌」仍然成立，所以措辞里保留了它：完整背景先写在回复里，工具只承载选择本身。
- 本仓 `AGENTS.md` 的「Asking questions」同步改为优先用提问工具。
- 随包带的 `package/bundled-skills/grilling/SKILL.md` 是上游 `mattpocock/skills v1.3.2` 的原样副本，维护者在 #43 决定保持原样、不打本地补丁，所以该技能仍会显示手写的「❓ **Q1**」格式。

## 仍然没有做的

- 面板动作表不增加「提问」这一种动作类型：面板一侧调不到 agent 的工具，唯一的杠杆仍是注入一段文字（见下面第 1 条）。
- 动作会话的预设模式没有改。
- 提示词里不写「没有提问工具时不许手写」这类禁令：工具在会话里是否存在由宿主的工具清单决定。

## 当时为什么不采纳（2026-10-28 的判断，仅作历史）

分三层看，任何一层单独成立都足以让它出圈：

1. **落点对不上**：`ask_user_question` 是 agent 侧的工具。面板与检查链这一侧根本调不到它；面板的动作类型只有注入提示、打开链接、远程调用、表单、刷新、向导这几种，唯一能让 agent 去提问的杠杆是「注入一段文字」。给动作表加一种类型，不会让 agent 真的去弹框。
2. **信息形态不匹配**：问答卡片只装得下选项标签和一小段自定义文本，装不下要给人读全的多段方案。问「A/B/C 选哪个」时，方案正文在对话里、卡片占着编辑器位置，人点选时看不到全貌，容易做无效决策（维护者 2026-10-28 的判断）。宿主的卡片现在是附着式的，旧理由「弹窗挡住正文解释」对今天的实现已不成立；本仓 `AGENTS.md` 的「提问方式」只是开发本仓时的约定、不随插件发布，也不能当产品理由。
3. **现有做法已经覆盖**：检查链的补充信息模板、讨论模板本来就是按对话正文提问的（`tpl.supplement` 的「问用户（逐条可直接回答）」、`tpl.discuss` 的「按本模板原有提问格式提出」）。真正需要补的是「什么时候该问」，不是「用什么控件问」。
